Lakeflow Connect vs a classic JDBC job

Lakeflow Connect (SQL Server / PostgreSQL)Classic JDBC job
Incremental loadsBuilt in: reads change tracking or CDC, so only changed rowsCustom: watermark columns, merge logic, state
DeletesCaptured automaticallyLost unless soft-delete or full-compare logic is built
History (SCD Type 2)A setting per tableCustom code
Schema changesNew and dropped columns handled automaticallyJob breaks or needs code changes
Initial + incremental loadOne setup: snapshot first, then changesTwo code paths to build and maintain
Load on the sourceLight: reads the change logsRepeated queries or scans on the database
RecoveryResumes where it stopped; automatic full refresh if change logs expireCustom retry and backfill logic
EffortPoint-and-click or a small configuration file, no codeOne notebook per source to maintain
CostDaily triggered pull about $9 / month; always-on gateway about $447 / month. Mostly Azure VMs: the DBUs of one source server are covered by the free tier (100 DBUs per day)A few minutes of a small classic cluster per day: about $5 to $10 / month (DBUs + VMs), no free tier
PrerequisitesChange tracking or CDC on the source tables; primary instance; gateway driver of at least 8 coresRead access over JDBC
NetworkGateway in your VNet, over the site-to-site VPNClassic cluster in your VNet, over the site-to-site VPN
For daily loads both cost about $10 per month. Lakeflow Connect replaces the hand-written incremental, delete and schema logic. JDBC remains useful for small reference tables or sources without a Lakeflow Connect connector.
